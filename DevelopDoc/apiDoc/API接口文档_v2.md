## 未完成功能规划（按优先级排序）

### Phase 4: 文档管理增强 🔴 高优先级

**目标**: 建立完整的用户体系，实现安全的多租户架构

**核心功能**:

1. **用户注册** (`POST /auth/register`)
   - 功能定义：允许新用户通过邮箱注册账号
   - 实现要点：
     - 验证邮箱格式和密码强度（8-32字符，包含字母数字）
     - 使用bcrypt加密存储密码
     - 可选：发送邮箱验证链接
     - 返回用户基本信息（不含敏感数据）
   - 数据流程：前端提交 → 参数验证 → 密码加密 → 数据库存储 → 返回结果

2. **用户登录** (`POST /auth/login`)
   - 功能定义：验证用户身份并颁发访问令牌
   - 实现要点：
     - 支持用户名或邮箱登录
     - 验证密码正确性
     - 生成AccessToken（24小时有效）和RefreshToken（7天有效）
     - 记录登录时间和IP地址
   - Token设计：JWT格式，包含用户ID、角色、过期时间

3. **用户登出** (`POST /auth/logout`)
   - 功能定义：使当前Token失效
   - 实现要点：
     - 将Token加入Redis黑名单
     - 设置过期时间与Token一致
     - 清除客户端存储的Token

4. **刷新Token** (`POST /auth/refresh`)
   - 功能定义：使用RefreshToken获取新的AccessToken
   - 实现要点：
     - 验证RefreshToken有效性
     - 检查是否在黑名单中
     - 生成新的AccessToken
     - 可选：同时刷新RefreshToken（滑动窗口）

5. **获取用户信息** (`GET /auth/me`)
   - 功能定义：获取当前登录用户的详细信息
   - 返回内容：用户资料、使用统计、存储配额

**技术方案**:
- 认证框架：FastAPI OAuth2PasswordBearer
- Token生成：python-jose库
- 密码加密：passlib + bcrypt
- 限流保护：slowapi（登录接口5次/分钟）

**数据库设计**:
- users表：存储用户基本信息
- token_blacklist表：存储失效的Token

### Phase 4: 文档管理增强 🔴 高优先级（下一步开发）

**目标**: 支持多轮对话，提供更自然的交互体验

**核心功能**:

1. **创建对话会话** (`POST /conversations`)
   - 功能定义：创建新的对话上下文
   - 参数说明：
     - title: 对话标题（可选，默认自动生成）
     - documentIds: 关联的文档列表（可选）
   - 实现逻辑：
     - 生成唯一会话ID
     - 初始化上下文窗口
     - 关联指定文档（如果提供）
     - 返回会话信息

2. **对话消息管理** (`POST /conversations/{id}/messages`)
   - 功能定义：在会话中发送消息并获取回复
   - 上下文管理策略：
     - 保留最近10轮对话
     - 超出限制时使用摘要压缩历史
     - 维护文档引用关系
   - 消息处理流程：
     - 加载历史上下文
     - 构建完整Prompt（系统提示 + 历史 + 当前问题）
     - 调用LLM生成回复
     - 保存消息记录
     - 更新会话状态

3. **对话列表查询** (`GET /conversations`)
   - 功能定义：获取用户的所有对话会话
   - 排序规则：按最后更新时间倒序
   - 返回信息：会话ID、标题、消息数、最后消息预览

4. **对话导出** (`GET /conversations/{id}/export`)
   - 功能定义：导出对话记录为文件
   - 支持格式：
     - Markdown：适合阅读和分享
     - PDF：适合打印和存档
     - JSON：适合数据分析
   - 导出内容：完整对话历史、思考过程、引用来源

**技术方案**:
- 上下文存储：PostgreSQL（持久化）+ Redis（活跃会话缓存）
- 上下文压缩：使用摘要模型或规则压缩
- 导出实现：使用markdown2、reportlab等库

**数据库设计**:
- conversations表：会话元数据
- messages表：消息记录（关联会话ID）

### Phase 4: 文档管理增强 🟡 中优先级

**核心功能**:

1. **批量上传** (`POST /documents/batch-upload`)
   - 功能定义：一次上传多个文档（最多10个）
   - 实现方式：
     - 使用异步任务队列（Celery）处理
     - 每个文档独立处理，互不影响
     - 返回批次ID和各文档状态
   - 错误处理：部分失败不影响其他文档

2. **标签系统** (`POST /documents/{id}/tags`)
   - 功能定义：为文档添加分类标签
   - 标签管理：
     - 支持自定义标签
     - 标签自动补全
     - 统计标签使用频率
   - 应用场景：按标签筛选、分类浏览

3. **文档分享** (`POST /documents/{id}/share`)
   - 功能定义：生成临时分享链接
   - 分享控制：
     - 设置过期时间（1小时-7天）
     - 可选访问密码
     - 控制是否允许下载
     - 记录访问次数
   - 安全措施：使用随机Token，定期清理过期链接

4. **版本管理** (数据库设计)
   - 功能定义：保留文档的历史版本
   - 版本策略：
     - 每次更新创建新版本
     - 保留最近5个版本
     - 支持版本回滚
   - 存储优化：使用差异存储减少空间占用

**技术方案**:
- 异步处理：Celery + Redis
- 文件存储：本地文件系统或对象存储（MinIO/S3）
- 分享Token：使用UUID或短链接服务

### Phase 5: 高级检索功能 🟡 中优先级

**目标**: 提升检索质量和用户体验

**开发优先级**: 🟡 中优先级

**预计工期**: 2-3周

**核心功能**:

1. **多文档联合检索** (`POST /query/multi-doc`)
   - 功能定义：跨多个文档进行综合检索
   - 实现策略：
     - 对每个文档独立检索
     - 使用RRF算法融合结果
     - 保留文档来源信息
   - 应用场景：对比分析、综合问答

2. **检索结果重排序** (`POST /query/rerank`)
   - 功能定义：使用专门模型优化检索结果排序
   - Rerank模型选择：
     - bge-reranker-base（中文优化）
     - cohere-rerank（英文优化）
   - 实现流程：
     - 初步检索获取候选集（top 20-50）
     - Rerank模型重新打分
     - 返回top K结果
   - 性能优化：缓存Rerank结果

3. **相似问题推荐** (`GET /query/suggestions`)
   - 功能定义：基于历史推荐相关问题
   - 推荐算法：
     - 计算问题向量相似度
     - 考虑问题热度（查询频率）
     - 过滤重复和低质量问题
   - 返回格式：问题文本 + 相似度分数

**技术方案**:
- Rerank模型：使用Sentence-Transformers加载
- 相似度计算：余弦相似度
- 缓存策略：Redis缓存热门查询

### Phase 6: 智能分析功能 🟢 低优先级

**目标**: 提供文档分析和洞察功能

**开发优先级**: 🟢 低优先级

**预计工期**: 3-4周

**核心功能**:

1. **文档摘要生成** (`POST /analysis/summary`)
   - 功能定义：自动生成文档摘要
   - 摘要策略：
     - 抽取式：提取关键句子
     - 生成式：使用LLM重新表述
     - 混合式：结合两种方法
   - 参数控制：
     - maxLength：摘要长度限制
     - style：摘要风格（简洁/详细）
   - 质量保证：确保摘要覆盖核心内容

2. **关键词提取** (`POST /analysis/keywords`)
   - 功能定义：提取文档关键词和主题
   - 提取方法：
     - TF-IDF：统计方法
     - TextRank：图算法
     - LLM提取：语义理解
   - 返回内容：关键词 + 权重分数 + 出现频率

3. **文档对比** (`POST /analysis/compare`)
   - 功能定义：对比两个文档的异同
   - 对比维度：
     - 内容相似度（整体）
     - 共同主题
     - 独特内容
     - 结构差异
   - 可视化：生成对比报告

4. **相似文档推荐** (`GET /analysis/similar/{id}`)
   - 功能定义：推荐与指定文档相似的其他文档
   - 相似度计算：
     - 文档向量相似度
     - 主题重叠度
     - 关键词匹配度
   - 推荐策略：综合多个指标排序

**技术方案**:
- 摘要生成：LLM + 提示工程
- 关键词提取：jieba + sklearn（TF-IDF）
- 文档对比：difflib + 语义相似度

### Phase 8: 系统稳定性增强 🟢 低优先级

**目标**: 提升系统可靠性和容错能力

**开发优先级**: 🟢 低优先级

**预计工期**: 2-3周

**核心概念**:

1. **服务熔断机制**
   - 定义：当服务异常率超过阈值时，自动切断请求，防止雪崩
   - 状态转换：
     - Closed（正常）→ Open（熔断）→ Half-Open（半开）→ Closed
   - 熔断条件：
     - 错误率 > 50%
     - 连续失败次数 > 5次
     - 响应超时 > 10秒
   - 恢复策略：熔断后等待60秒尝试恢复

2. **优雅降级策略**
   - 定义：在系统压力大时，关闭非核心功能，保证核心服务
   - 降级级别：
     - L1：关闭推荐功能
     - L2：关闭Thinking Chain
     - L3：限制并发查询数
   - 触发条件：CPU > 80%、内存 > 90%、队列积压 > 100

3. **请求重试机制**
   - 定义：失败请求自动重试，提高成功率
   - 重试策略：
     - 指数退避：1s、2s、4s、8s
     - 最大重试次数：3次
     - 幂等性保证：使用请求ID去重
   - 适用场景：网络抖动、临时故障

4. **备用模型切换**
   - 定义：主模型不可用时自动切换到备用模型
   - 模型配置：
     - 主模型：qwen3-vl:2b-thinking
     - 备用模型：qwen2:7b
   - 切换条件：
     - 主模型连续失败3次
     - 主模型响应超时
   - 恢复检测：每5分钟检测主模型是否恢复

**实施方法**:
- 熔断器：使用pybreaker库
- 降级控制：配置中心动态调整
- 重试机制：使用tenacity库
- 模型切换：配置多个Ollama实例

## 扩展数据模型

### 新增模型定义

**User（用户）**:
```
字段说明：
- id: 用户唯一标识（UUID）
- username: 用户名（3-20字符，唯一）
- email: 邮箱地址（唯一）
- passwordHash: 密码哈希值
- role: 用户角色（admin/user）
- avatar: 头像URL
- isActive: 账号状态
- createdAt: 注册时间
- lastLoginAt: 最后登录时间
```

**Conversation（对话）**:
```
字段说明：
- id: 对话唯一标识
- userId: 所属用户ID
- title: 对话标题
- documentIds: 关联文档ID列表
- messageCount: 消息数量
- lastMessage: 最后一条消息预览
- createdAt: 创建时间
- updatedAt: 更新时间
```

**Message（消息）**:
```
字段说明：
- id: 消息唯一标识
- conversationId: 所属对话ID
- role: 角色（user/assistant）
- content: 消息内容
- thinking: 思考过程（仅assistant）
- sources: 引用来源（仅assistant）
- createdAt: 创建时间
```

**DocumentTag（文档标签）**:
```
字段说明：
- id: 标签唯一标识
- name: 标签名称
- color: 标签颜色
- documentCount: 使用该标签的文档数
- createdAt: 创建时间
```

**ShareLink（分享链接）**:
```
字段说明：
- id: 分享唯一标识
- documentId: 文档ID
- token: 分享Token（随机生成）
- password: 访问密码（可选）
- allowDownload: 是否允许下载
- expiresAt: 过期时间
- accessCount: 访问次数
- createdBy: 创建者ID
- createdAt: 创建时间
```
