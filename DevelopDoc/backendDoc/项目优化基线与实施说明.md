# 项目优化基线与实施说明

## 1. 本次优化目标

- 以“不破坏 `/api/v1` 现有契约”为前提，优先解决可维护性、前后端构建质量和测试基线问题。
- 先补验证基线，再做结构收敛，避免优化过程本身不可回归。
- 保持当前功能行为不变，只做内部边界、构建和交付能力优化。

## 2. 优化前体检

- 后端热点文件：
  - `backend/app/api/v1/conversations.py` 约 `645` 行
  - `backend/app/api/v1/documents.py` 约 `634` 行
  - `backend/app/services/embedding_service.py` 约 `382` 行
- 前端热点文件：
  - `frontend/src/features/documents/pages/documents-page.tsx` 约 `942` 行
  - `frontend/src/features/workspace/pages/workspace-page.tsx` 约 `609` 行
- 前端打包基线：
  - `npm run build` 产物主包约 `733 kB`
  - Vite 明确给出 `chunk > 500 kB` 告警
- 测试与环境基线：
  - 后端本地环境存在 `pluggy` / `iniconfig` / `fastapi` 等缺失问题
  - `DocumentProcessor` 顶层加载 `PaddleOCR`，导致非 OCR 测试也被重依赖阻塞

## 3. 本次已落地改动

### 3.1 后端

- 配置硬化
  - `backend/app/config.py`
  - 新增 `environment` 与 `cors_allowed_origins`
  - 支持 `CORS_ALLOWED_ORIGINS` 的 CSV / JSON 解析
  - 生产环境禁止弱 `SECRET_KEY` 与 `*` CORS
- 外部调用边界
  - 新增 `backend/app/services/clients/ollama_client.py`
  - 统一封装 Ollama 普通请求与流式请求
  - `LLMService` / `EmbeddingService` 改为通过客户端调用，减少散落的同步 HTTP 逻辑
- 服务与依赖加载优化
  - `backend/app/services/__init__.py` 不再在包导入阶段拉起重量级依赖
  - `backend/app/dependencies.py` 改为惰性导入服务实现
  - `backend/app/services/document_processor.py` 改为按需加载 `PaddleOCR`
- 路由瘦身
  - 新增 `backend/app/services/conversation_message_service.py`
  - 新增 `backend/app/services/document_route_service.py`
  - `conversations.py` 与 `documents.py` 仅保留路由编排，主逻辑下沉到服务层

### 3.2 前端

- 路由懒加载
  - `frontend/src/app/router/index.tsx`
  - 登录、注册、分享、工作台、文档、分析页面改为 `React.lazy + Suspense`
- 包体拆分
  - `frontend/vite.config.ts`
  - 新增 `manualChunks`，将 router / data / markdown / react vendor 拆包
- 页面逻辑抽离
  - 新增 `frontend/src/features/documents/preview-utils.tsx`
  - 新增 `frontend/src/features/workspace/message-utils.ts`
  - 页面文件移除重复的状态/预览/草稿消息辅助逻辑

## 6. 常见问题

- `pytest` 启动缺少 `pluggy` / `iniconfig`
  - 说明当前 Python 环境未按项目依赖装齐，先执行依赖安装再跑测试。
- 非 OCR 场景导入 `DocumentProcessor` 报 `paddleocr` 缺失
  - 当前版本已改为惰性加载；只有真正执行 OCR 时才需要安装完整 OCR 栈。
- `.pytest_cache` 权限告警
  - 这类告警不影响编译与测试结果，但建议本地检查目录权限，避免缓存写入失败。
- 当前工作区有未提交改动
  - 继续做大改前，建议先隔离分支或整理工作区，避免把优化改动和业务开发混在一起。

## 7. 后续建议

- 继续把 `documents-page.tsx` / `workspace-page.tsx` 的查询编排进一步下沉到 hooks 和子组件。
- 将后端批量上传、标签、分享等剩余路由继续按子域拆分。
- 如需把 Docker Compose 作为正式交付路径，建议下一步补齐后端服务容器与健康检查说明。
