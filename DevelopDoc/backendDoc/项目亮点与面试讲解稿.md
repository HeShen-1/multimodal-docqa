# 项目亮点与面试讲解稿

## 1. 项目定位

这是一个面向企业知识库场景的**多模态文档问答系统**，目标不是单纯接一个大模型接口，而是把：

- 文档上传与解析
- OCR / 表格抽取
- 检索增强问答
- 流式回答
- 评测与工程化交付

串成一条完整、可解释、可展示的链路。

## 2. 我重点优化了什么

### 检索主链路

- 将主链路统一为：`query rewrite -> hybrid recall -> parent context merge -> optional rerank -> grounded answer`
- 为每次问答记录 `retrieval_strategy`、`rewritten_query`、`top_score`、`evidence_coverage`
- 当证据不足时，不强行生成答案，而是返回“未找到足够依据”

### 多模态文档处理

- 对 PDF / DOCX / Markdown / CSV / JSON / HTML / XML 建立统一处理入口
- OCR 结果不再只保留纯文本，同时保留块级信息
- 表格文件按“表头 + 行字段”重写成结构化文本，提升检索可用性

### 可观测性与展示性

- 流式 `done` 事件返回 `model_name`、`latency_ms`、`retrieved_chunks`、`citation_count`、`fallback_reason`
- 文档详情增加 `processingSummary`，可以直观看到 `extractMethod`、`ocrUsed`、`hasTables`
- 前端把“答案、来源、思考、响应元数据”拆开展示，避免黑盒问答

## 3. 面试时可以这样讲

### 为什么不是只做微调？

因为这个岗位更看重 **LLM 应用落地能力**。对于文档问答场景，优先级通常是：

1. 文档解析质量
2. 检索召回与重排
3. 引用与拒答策略
4. 服务化与可观测性
5. 轻量微调加分

所以我把微调定位为加分项，而不是主链路。

### 为什么做拒答？

如果检索证据不足还继续回答，就很容易出现幻觉。  
我在链路里增加了 `top_score` 和 `evidence_coverage` 判断，当证据不足时直接返回 grounded no-answer，这比“答得像”更重要。

### 多模态体现在哪里？

我没有把多模态理解成“接一个大 VLM 模型”，而是把企业文档里的：

- 原生 PDF
- 扫描件 OCR
- 表格型文档

统一纳入可检索问答链路，这对企业知识库更实用。
